# nRF52 e-paper tag

[EN](README.md) · **RU**

Прошивка для электронных ценников на nRF52832 с e-ink дисплеем 2.9" BWR
(контроллер класса SSD1675A). Управление по BLE. Документации на них не
существует.

Началось всё с Авито. Сначала — пятёрка ценников по 250 ₽, из которых половина
приехала битой и залитой электролитом. Потом ещё семнадцать от того же
продавца, из них живых оказалось пара штук. А потом — целая коробка, забитая
ценниками до краёв, за 500 ₽. Для сравнения: один такой же e-ink дисплей на
AliExpress стоил тогда 700 ₽.

Внутри каждого — nRF52832 и e-ink панель. Ни SDK, ни даташита, ни распиновки;
производитель на письмо не ответил. Всё, что есть в этом репозитории —
распиновка, таблицы волновых форм, режимы обновления, стриминг — добыто
экспериментами на живой панели и записано в [`docs/`](docs/).

Как эти ценники вскрывались:
[Как я купил кота в мешке: реверс-инжиниринг электронных ценников](https://habr.com/ru/articles/1044406/).

> **Когда прошивка уже залита, тулчейн больше не нужен:**
> <https://pwa.price-tag.sorewa.ru/> — веб-приложение, которое управляет
> ценником по Web Bluetooth прямо из браузера: картинки, анимация, редактор
> волновых форм, обновление по воздуху. Нужен Chrome или Edge на компьютере
> либо на Android.
>
> Один раз прошить всё же придётся по проводу: на стоковом ценнике стоит
> прошивка производителя, и он не отдаёт в эфир ничего, к чему приложение могло
> бы подключиться. Как это сделать — [ниже](#сборка). Дальше всё по воздуху.

## Что умеет

- Рисует часы, статус и заставку на экране 128×296 в трёх цветах:
  чёрный, белый, красный
- Крутит анимацию и видео по BLE — ~110 мс на кадр там, где стоковое полное
  обновление занимало 9 секунд
- Принимает команды по Nordic UART Service: из консоли, из десктопного GUI или
  из [браузера](https://pwa.price-tag.sorewa.ru/)
- Обновляется по воздуху (MCUboot, две подписанные партии) оттуда же
- Раскидывает команды от ценника к ценнику через flood-mesh без подключений —
  одного соединения с телефоном хватает на весь парк

## Самое интересное

- [`lib/`](lib/) — драйвер дисплея и графика, вынесенные в **отдельную
  библиотеку на C99 без единой зависимости**. Ни Zephyr, ни nRF SDK: от железа
  её отделяют шесть функций. В комплекте готовые порты под Zephyr, Arduino и
  STM32 HAL — забрать можно как есть.
- [`docs/eink-lut-reference.md`](docs/eink-lut-reference.md) — формат таблицы
  волновых форм SSD1675A, разобранный по байтам: что означает каждая строка
  LUT, как на самом деле считается RP, формула времени обновления и
  арифметика DC-баланса, без которой панель выгорает.
- [`docs/display-optimization.md`](docs/display-optimization.md) — как частичное
  обновление проехало путь с 762 мс до 112 мс. Вместе с двумя тупиками и
  выжженным в экран Game of Life, который из них получился.

## Железо

| Компонент | Что стоит                                                     |
| --------- | ------------------------------------------------------------- |
| МК        | nRF52832 — 512 КБ флеша, 64 КБ RAM                            |
| Дисплей   | класс SSD1675A, 128×296, чёрный/белый/красный                 |
| Шина      | программный 9-битный SPI: бит D/C панель ждёт внутри кадра    |
| Плата     | таргет `nrf52dk/nrf52832`                                     |

Пины по умолчанию — те самые, что были вызвонены под микроскопом
(переопределяются через `SSD1675A_PIN_*` из системы сборки):

| Сигнал | Пин |
| ------ | --- |
| BUSY   | 6   |
| RST    | 7   |
| CS     | 8   |
| CLK    | 11  |
| MOSI   | 12  |
| VCC    | 19  |

## Сборка

Нужен nRF Connect SDK v3.0.1. Если он стоит в другом месте — скажи Makefile,
где искать:

```sh
make                                   # собрать и упаковать OTA-образ
make NCS_DIR=/opt/nordic/ncs/v3.0.1 BOARD=nrf52dk/nrf52832
make flash                             # west flash
make clean
```

Из одного дерева исходников собираются два варианта OTA — матрица расписана в
[`Makefile`](Makefile):

```sh
make                # партия legacy: текущая разметка, ключ подписи по умолчанию
make VARIANT=v2     # партия v2: свой ключ подписи, раздел factory_data
make release        # обе, слитые в один манифест
```

Сборка специально падает, если образ не влезет в OTA-слот. Иначе MCUboot такой
образ примет, отметит как test — и молча не применит.

### Первая прошивка

Стоковый ценник придётся один раз прошить по проводу: беспроводного пути внутрь
нет, пока там не окажется эта прошивка. Внутри Cortex-M4, поэтому подойдёт
любой CMSIS-DAP-программатор — WCH-LinkE в режиме CMSIS-DAP, ST-Link, J-Link.
Фирменный программатор Nordic за конские деньги не нужен.

Паяться надо к SWDIO и SWCLK. Площадки под них разные от ревизии к ревизии,
даже если снаружи ценники выглядят одинаково, так что прозванивай.

```sh
make flash            # west flash, если программатор ему знаком
make flash-openocd    # openocd из командной строки, поднимает свою сессию
make flash-gdb        # уже запущенный OpenOCD, telnet localhost:4444
make flash-retry      # долбить, пока не сверится
```

`make flash-retry` появился не от хорошей жизни: контакт на этих платах
отваливается, поэтому скрипт просто перепрошивает до успешной верификации.
Дальше всё обновляется по BLE.

## Как с ним разговаривать

Команды прилетают по Nordic UART Service — либо текстом (`MODE:3`, `NUKE:5`,
`TIME=…`), либо бинарными opcode-кадрами. И то, и другое уходит в один реестр
[`src/app/cmd_opcodes.h`](src/app/cmd_opcodes.h), так что каждая команда
написана ровно один раз. `HELP` покажет всё, что умеет залитая прошивка.

### Из браузера, без установки

[`lut_tester_host/web/`](lut_tester_host/web/) выложен и доступен всем:
**<https://pwa.price-tag.sorewa.ru/>**. Это то же самое приложение, что лежит в
репозитории, со всем, что оно умеет: картинки с дизерингом, текст, анимация и
видео, редактор 70-байтной волновой формы с графиком и полосами DC-баланса,
режимы дисплея и заставки, время, батарея, статистика, обновление по воздуху на
[`/dfu.html`](https://pwa.price-tag.sorewa.ru/dfu.html).

Общается с ценником по Web Bluetooth прямо из вкладки — на компьютере ничего
ставить не надо. **Увидит оно только ценники с этой прошивкой** — стоковую
прошивку производителя оно не найдёт. Это PWA: ставится как приложение и
работает офлайн после первой загрузки. Web Bluetooth есть в Chrome, Edge и
Opera на десктопе и на Android; в Safari, на iOS и в Firefox его нет.

Внутри обычная статика, так что поднимется на любом хосте — выкладывает
`make deploy`.

### Из терминала

```sh
pip install -r lut_tester_host/requirements.txt
python3 lut_tester_host/lut_tester.py          # GUI: редактор LUT и управление
python3 lut_tester_host/vstream_player.py …    # стриминг видео на панель
python3 lut_tester_host/dfu_upload.py …        # обновление из командной строки
```

## Забрать код дисплея себе

`lib/` писалась с расчётом на то, что её вынут отсюда и положат в свой проект.
Она не тянет за собой ни Zephyr, ни nRF SDK, ни что-либо ещё из репозитория:
между драйвером и железом стоят шесть функций (`ssd1675a_port.h`), а в
`lib/eink/port/` уже лежат рабочие реализации под Zephyr, Arduino и STM32 HAL.

Что именно надо написать под свою платформу и примеры для копирования — в
[`lib/README.md`](lib/README.md).
