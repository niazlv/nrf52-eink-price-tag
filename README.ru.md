# nRF52 e-paper tag

[EN](README.md) · **RU**

Прошивка для перепрофилированного электронного ценника 2.9" BWR — nRF52832,
который управляет e-ink панелью SSD1675A и принимает команды по BLE. Никакой
документации от производителя на всё это нет.

Панель приехала в мешке списанных ценников, купленных на классифайдах за
копейки: без документации, без SDK и без вендора, готового ответить. Всё, что
здесь есть — распиновка, таблицы волновых форм, режимы обновления, стриминг —
отреверсено на столе и описано в [`docs/`](docs/).

История о том, как ценники были вскрыты:
[Как я купил кота в мешке: реверс-инжиниринг электронных ценников](https://habr.com/ru/articles/1044406/).

> **Как только на ценнике оказалась эта прошивка, тулчейн больше не нужен:**
> <https://pwa.price-tag.sorewa.ru/> — живое веб-приложение, которое управляет
> им по Web Bluetooth: картинки, анимация, редактор волновых форм, OTA-обновления.
> Chrome или Edge на десктопе либо на Android.
>
> Загвоздка — первая прошивка. На стоковом ценнике стоит прошивка производителя,
> и он не анонсирует ничего, с чем это приложение может заговорить, поэтому его
> придётся один раз прошить по SWD ([см. ниже](#сборка)). Дальше всё
> беспроводное.

## Что оно умеет

- Рисует часы, статус и заставку на панели 128×296 чёрный-белый-красный
- Стримит анимацию и видео на панель по BLE за ~110 мс на кадр — при том, что
  стоковое полное обновление занимало ~9 с
- Принимает команды по Nordic UART Service: из CLI, из десктопного GUI или из
  [веб-приложения](https://pwa.price-tag.sorewa.ru/)
- Обновляет себя по воздуху (MCUboot, подпись двух вариантов) из того же
  веб-приложения
- Ретранслирует команды от ценника к ценнику по connectionless flood-mesh, так
  что одно подключение с телефона достаёт до всего парка

## Главное

- [`lib/`](lib/) — драйвер дисплея и графика как **портируемая библиотека на
  C99 без зависимостей**. Ни Zephyr, ни nRF SDK: от платформы её отделяют шесть
  функций, в комплекте готовые порты под Zephyr, Arduino и STM32 HAL.
- [`docs/eink-lut-reference.md`](docs/eink-lut-reference.md) — побайтовый формат
  таблицы волновых форм SSD1675A, разобранный экспериментально: семантика строк
  LUT, правило повторов RP, формула времени и арифметика DC-баланса, которая
  удерживает панель от выгорания.
- [`docs/display-optimization.md`](docs/display-optimization.md) — как частичное
  обновление с 762 мс дошло до 112 мс, вместе с двумя тупиками и выгоранием,
  которое они принесли.

## Железо

| Часть  | Значение                                                            |
| ------ | ------------------------------------------------------------------- |
| МК     | nRF52832 (512 КБ флеша, 64 КБ RAM)                                  |
| Панель | класса SSD1675A, 128×296, чёрный/белый/красный                      |
| Шина   | программный 9-битный SPI (бит D/C панель ждёт внутри кадра)         |
| Плата  | таргет `nrf52dk/nrf52832`                                           |

Распиновка по умолчанию (переопределяется через `SSD1675A_PIN_*` из системы
сборки):

| Сигнал | Пин |
| ------ | --- |
| BUSY   | 6   |
| RST    | 7   |
| CS     | 8   |
| CLK    | 11  |
| MOSI   | 12  |
| VCC    | 19  |

## Сборка

Нужен nRF Connect SDK v3.0.1. Если он лежит в другом месте, укажи путь Makefile:

```sh
make                                   # сборка + упаковка OTA-образа
make NCS_DIR=/opt/nordic/ncs/v3.0.1 BOARD=nrf52dk/nrf52832
make flash                             # west flash
make flash-retry                       # прошивать, пока не сверится (плохой контакт SWD)
make clean
```

Из одного дерева исходников собираются два OTA-варианта — матрица вариантов
описана в [`Makefile`](Makefile):

```sh
make                # партия legacy: текущая разметка, ключ подписи по умолчанию
make VARIANT=v2     # партия v2: свой ключ подписи, раздел factory_data
make release        # оба, слитые в один манифест
```

Проверка размера OTA роняет сборку до публикации образа, который MCUboot
примет, но молча откажется применить.

### Первая прошивка

Стоковый ценник придётся один раз прошить по SWD — беспроводного пути внутрь
нет, пока на нём не окажется эта прошивка. Ядро nRF52832 — Cortex-M4, поэтому
годится любой CMSIS-DAP-программатор: WCH-LinkE в режиме CMSIS-DAP, настоящий
ST-Link или J-Link. Фирменный программатор Nordic не нужен ни одному из них.
Припаяться нужно к площадкам SWDIO/SWCLK — они отличаются от ревизии к ревизии,
так что прозвони.

```sh
make flash            # west flash, для программаторов, которые west знает
make flash-openocd    # openocd CLI, поднимает свою сессию
make flash-gdb        # уже запущенный OpenOCD на telnet localhost:4444
make flash-retry      # прошивать, пока не сверится — для плохого контакта SWD
```

`make flash-retry` существует именно потому, что контакт pogo-пинов на этих
платах ненадёжный: он перепрошивает, пока верификация не пройдёт. После этого
все дальнейшие обновления идут по BLE.

## Как общаться с ценником

Команды приходят по Nordic UART Service текстовыми строками (`MODE:3`,
`NUKE:5`, `TIME=…`) либо бинарными opcode-кадрами. И то, и другое диспетчеризуется
через один реестр в [`src/app/cmd_opcodes.h`](src/app/cmd_opcodes.h), так что
каждая команда реализована ровно один раз. `HELP` перечисляет всё, что знает
запущенная прошивка.

### Из браузера — без установки

[`lut_tester_host/web/`](lut_tester_host/web/) развёрнут и открыт для всех по
адресу **<https://pwa.price-tag.sorewa.ru/>**. Это то же самое приложение, что
лежит в этом репозитории, со всем, что оно умеет: картинки с дизерингом, текст,
анимация и стриминг видео, редактор 70-байтной волновой формы с живым графиком
и полосами DC-баланса, заставка и режимы дисплея, время, батарея и статистика,
OTA-обновления на [`/dfu.html`](https://pwa.price-tag.sorewa.ru/dfu.html).

Оно говорит с ценником по Web Bluetooth прямо из браузера — на хосте ничего
собирать и ставить не надо. **Оно видит только те ценники, на которых уже стоит
эта прошивка**, поэтому стоковый сначала нужно один раз прошить по проводу:
стоковая прошивка производителя не анонсирует ничего, к чему это приложение
могло бы подключиться. Это PWA — ставится как приложение и продолжает работать
офлайн после первой загрузки. Web Bluetooth означает Chrome, Edge или Opera на
десктопе и на Android; Safari, iOS и Firefox его не реализуют.

Это статическая сборка, поэтому она поднимется на любом хосте, на который её
положишь — публикует `make deploy`.

### Из терминала

```sh
pip install -r lut_tester_host/requirements.txt
python3 lut_tester_host/lut_tester.py          # GUI: редактор LUT + управление
python3 lut_tester_host/vstream_player.py …    # стриминг видео на панель
python3 lut_tester_host/dfu_upload.py …        # OTA из командной строки
```

## Как переиспользовать код дисплея

`lib/` написана так, чтобы её можно было вынуть из этого репозитория. У неё нет
зависимости ни от Zephyr, ни от nRF SDK, ни от чего-либо ещё отсюда: между
драйвером и железом стоят шесть функций (`ssd1675a_port.h`), а в каталоге
`lib/eink/port/` лежат рабочие реализации для Zephyr, Arduino и STM32 HAL.

Контракт порта и примеры для копирования — в [`lib/README.md`](lib/README.md).
